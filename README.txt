1. 环境要求
======================================================================

  [必需] Java 11 ~ 23
    下载: https://adoptium.net/ 或 https://www.oracle.com/java/
    验证: 打开命令行，输入 "java -version"
    如果已安装，启动器会自动检测 Java 版本

  [必需] Node.js 18+
    （仅桌面客户端模式需要）
    下载: https://nodejs.org/
    验证: 命令行输入 "node -v"

2. 快速启动
======================================================================

  方式一：一键启动器（推荐）
  ───────────────────────────────────────────────────────────────
    1. 双击 "StudyRoom Launcher.exe"
    2. 自动检测 Java → 启动后端 → 等待就绪 → 启动桌面客户端
    3. 使用完毕后关闭客户端窗口，后端自动停止

    流程详解:
      [1/3] 启动后端服务...
        → java -jar backend\studyroom.jar
        → 后端进程启动（PID: xxxx）

      [2/3] 等待后端服务就绪...
        → 每1秒检查一次 http://127.0.0.1:8082
        → 后端就绪后自动进入下一步
        → 最长等待 90 秒（通常只需 5~15 秒）

      [3/3] 启动桌面客户端...
        → npx electron . 启动 Electron 窗口

    特点:
      ✅ 一个 EXE 完成所有操作
      ✅ 关闭窗口自动停止后端，不残留 Java 进程
      ✅ 自动检测 Java 环境（如果没有 → 弹窗提示下载）
      ✅ 自动安装 Electron 依赖（首次运行）
      ✅ 有控制台窗口，启动过程一目了然
      ✅ 已数字签名（减少杀毒软件误报）

  方式二：浏览器模式（不需要 Node.js）
  ───────────────────────────────────────────────────────────────
    1. 进入 backend 文件夹
    2. 双击 start.bat
    3. 等待出现 "Started Application" 提示
    4. 打开浏览器访问: http://localhost:8082

    适合：只想用网页版、没有安装 Node.js 的情况。
    注意：关闭命令行窗口 = 停止后端服务器。

  方式三：桌面客户端（手动分步启动）
  ───────────────────────────────────────────────────────────────
    第1步  双击 backend\start.bat         ← 启动后端
    第2步  等待出现 "Started Application"
    第3步  双击 start-electron.bat         ← 启动桌面客户端

    特点：如需单独重启前端/后端，用此方式更灵活。
    关窗即缩小到系统托盘，右键托盘图标可退出。

3. 启动器 EXE 详解
======================================================================

  文件: StudyRoom Launcher.exe (约 12 KB)
  性质: C# 编译的 .NET 可执行文件（非脚本）
  目标: 一键启动整个系统

  工作目录结构要求:
    studyroom_submit/            ← EXE 所在目录
    ├── StudyRoom Launcher.exe  ← 启动器
    ├── backend/
    │   └── studyroom.jar       ← Spring Boot 后端
    └── electron_client/
        └── package.json        ← Electron 桌面客户端

  启动器做了什么:
    ① 检测 java 命令是否可用
    ② 检查 backend\studyroom.jar 是否存在
    ③ 检查 electron_client\package.json 是否存在
    ④ 启动 Java 进程（jar）
    ⑤ 轮询 HTTP 端口 8082，等待后端就绪
    ⑥ 启动 Electron 桌面客户端
    ⑦ 等待 Electron 窗口关闭
    ⑧ 自动 Kill 后端 Java 进程

  超时策略:
    - 每1秒检测一次后端端口
    - 最大等待 90 秒
    - 每 10 秒输出一次 "等待中..."
    - 超时后自动停止后端并弹出错误

  错误处理:
    - 所有错误通过 MessageBox 弹窗提示
    - 控制台窗口显示详细日志
    - 同时写入 launcher.log 日志文件

6. 数据库说明
======================================================================

  系统使用内嵌 H2 数据库（无需安装 MySQL）。

  数据文件位置:
    backend\data\studyroom.mv.db

  H2 控制台（仅开发调试用）:
    http://localhost:8082/h2-console
    JDBC URL: jdbc:h2:file:./data/studyroom
    用户名: sa（无密码）

  注意:
    - 删除 studyroom.mv.db 会清空所有数据（回到初始状态）
    - 数据文件默认在 backend/data/ 目录下
    - 不需要额外安装数据库管理系统

7. 邮箱配置
======================================================================

  系统支持邮箱验证功能（预约确认、密码重置等）。
  如需启用，请修改:

    backend_src\src\main\resources\application.yml

  找到以下配置:

    spring:
      mail:
        host: smtp.qq.com                 # SMTP 服务器地址
        port: 587                          # 端口
        username: your_email@qq.com        # 发件邮箱
        password: your_authorization_code  # 授权码（非登录密码）
        properties:
          mail.smtp.auth: true
          mail.smtp.starttls.enable: true

  常见邮箱 SMTP 配置:
  ───────────────────────────────────────────────────────────
  邮箱         SMTP 地址         端口    授权码说明
  QQ邮箱      smtp.qq.com        587    设置→账户→生成授权码
  163邮箱     smtp.163.com       465    设置→POP3/SMTP→开启
  Gmail       smtp.gmail.com     587    需 App Password

  注意:
    - password 填的是 邮箱授权码/App Password
    - 不是邮箱登录密码！
    - 不配置邮箱不影响核心功能（预约、签到等）

9. 常见问题排查
======================================================================

  Q: 双击 EXE 后没有反应？
  ───────────────────────────────────────────────────────────
    可能原因:
    - 没有 Java（launcher.log 中应有 "未找到 Java" 记录）
    - 文件路径有中文 → 当前已支持中文路径
    - 杀毒软件拦截 → 已数字签名，可将 EXE 加入信任区
    - .NET Framework 未安装 → 需要 .NET Framework 4.0+

    处理方法:
    ① 打开 launcher.log 查看错误信息
    ② 确认已安装 Java: 命令行输入 java -version
    ③ 确认 backend\studyroom.jar 存在
    ④ 确认 electron_client\package.json 存在

  Q: 后端启动失败/端口被占用？
  ───────────────────────────────────────────────────────────
    执行以下命令查看端口占用:
      netstat -ano | findstr :8082

    找到占用端口的 PID，在任务管理器中结束该进程。
    或者修改端口（见 start.bat 中的 --server.port=8082）。

  Q: 桌面客户端白屏/无法加载？
  ───────────────────────────────────────────────────────────
    原因: 后端未就绪时客户端已经启动
    解决:
    ① 确保后端先启动完毕（看到 "Started Application"）
    ② 或者使用 一键启动器（自动等待后端就绪）
    ③ 按 F12 打开开发者工具，查看 Console 面板报错

  Q: npm install 失败/Electron 启动慢？
  ───────────────────────────────────────────────────────────
    原因: npm 默认使用国外 registry，下载慢
    解决: 已配置 --registry=https://registry.npmmirror.com
    如果仍然失败，手动执行:
      cd electron_client
      npm install --registry=https://registry.npmmirror.com

  Q: 如何更换端口？
  ───────────────────────────────────────────────────────────
    修改 start.bat 中的端口参数:
      --server.port=8082    ← 改成你想要的端口（如 9090）
    同时修改 electron_client\main.js 中的 API 地址:
      http://localhost:8082 → http://localhost:9090

  Q: 如何重置数据？
  ───────────────────────────────────────────────────────────
    删除 backend\data\studyroom.mv.db 文件
    重启后端即可自动创建新数据库
    初始数据（测试账号）会自动插入

  Q: 杀毒软件报毒？
  ───────────────────────────────────────────────────────────
    这是误报，原因:
    - 启动器运行时执行 java 和 cmd 命令
    - 使用 Process.Start 创建子进程
    - 未签名或新签名尚未被信任
    解决方法:
    - 已将 EXE 数字签名，大部分杀毒软件不再拦截
    - 如果仍被拦截，添加信任/排除项即可
    - 源码 Launcher.cs 完全开源，可自行编译验证

  Q: 如何查看启动日志？
  ───────────────────────────────────────────────────────────
    每次启动会在 EXE 同目录生成 launcher.log
    用记事本打开即可查看完整的启动过程记录

10. FAQ
======================================================================

  问：这个系统需要联网吗？
  答：不需要。后端、前端都在本地运行，断网也能用。
      邮箱功能除外（需要连接 SMTP 服务器）。

  问：启动器能用于生产环境吗？
  答：启动器主要用于本地开发测试和演示。
      生产环境建议注册为 Windows 服务或使用 Docker。

  问：如何更新后端代码？
  答：修改 backend_src 中的源码，然后用 Maven 打包:
      cd backend_src
      mvn clean package -DskipTests
      生成的 jar 在 target/ 目录，复制到 backend/ 即可

  问：如何修改前端的 API 地址？
  答：修改 frontend_src 中对应的 API 配置
      （通常是 src/config.js 或 .env 文件）
      然后重新 build:
      cd frontend_src
      npm run build
      将 dist/ 目录的内容替换到后端静态资源目录

  问：支持多用户同时使用吗？
  答：支持。H2 数据库支持多连接，
      其他设备通过局域网 IP 访问即可
      （如 http://192.168.1.100:8082）

  问：数据会丢失吗？
  答：H2 数据库文件持久化在硬盘上，
      除非手动删除 studyroom.mv.db，否则数据不会丢失。
      建议定期备份 data/ 目录。
